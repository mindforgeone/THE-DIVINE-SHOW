# Марафон 120 дней

Трекер привычек, формы, профессионального роста и самовыражения. Перед стартом нужно принять шесть личных обязательств и записать смысл марафона. Стартовая дата подтверждается облачной транзакцией один раз.

## Что внутри

- карта 120 календарных дней от выбранного старта;
- редактируемые цели и связанные с ними задачи, действия и статистика;
- вес, питание, активность, шаги и ситуации смелости;
- немедленное сохранение каждого ввода на устройстве и повторная отправка в Firebase при восстановлении связи;
- полностью заполненный день сразу получает текущий результат и очки, оставаясь редактируемым до закрытия;
- прошедшие полностью заполненные дни закрываются автоматически при смене даты или следующем открытии; незаполненный недельный итог остаётся отдельным обязательством;
- частичные записи остаются в истории, графиках и экспорте;
- недельные итоги и отдельная форма на 120-й день;
- экспорт Markdown и JSON для анализа нейросетью.

Сброс от 06.09.2026 относится только к аккаунту, запросившему удаление. При его входе транзакция удаляет старые документы и создаёт маркер в новом пространстве истории. Повторные входы не сбрасывают начатый марафон. Остальные аккаунты продолжают использовать прежний документ. Адрес аккаунта не публикуется в конфигурации; используется отпечаток SHA-256.

## Запуск

```bash
npm install
npm run dev
```

## Проверка

```bash
npm run lint
npm test
npm run build
```

`tests/marathon.test.mjs` проверяет расчёт результата, автоматическое закрытие, отсутствие повторных очков, частичные записи, объединение полей с двух устройств, изоляцию сброса и обязательные подтверждения.

`tests/browser.mjs` запускается с установленным Playwright и работающим локальным сервером (`node tests/browser.mjs`). Параметры: `MARATHON_TEST_URL`, `MARATHON_TEST_OUTPUT`, при необходимости `PLAYWRIGHT_MODULE`. Тест подменяет Firebase изолированным хранилищем и использует вымышленные аккаунты: реальные облачные данные не затрагиваются. Проверяются телефон и компьютер, отключение сети, перезагрузка сразу после ввода, смена даты, блокировка дня и однократный сброс. Реальная авторизация Google и правила доступа Firebase требуют отдельной проверки в аккаунте.

`node tests/auth-browser.mjs` проверяет повторные нажатия входа, закрытое и заблокированное окно Google, сетевые ошибки, возвращение на мобильную вкладку во время загрузки, повторное уведомление о том же аккаунте, отказ в доступе к истории и восстановление без потери ввода. Отдельный сценарий использует настоящий Firebase Auth SDK с подменёнными сетевыми ответами: сессия сохраняется после перезагрузки, а запрет очистки старого локального кеша не блокирует вход. Данные и токены только тестовые; интерактивное согласие Google и конкретный браузер телефона этим не проверяются.

## Вход и восстановление

- Вход запускается только одним нажатием, без параллельных окон и без асинхронной подготовки перед открытием окна.
- Сохранение сессии остаётся штатным для `getAuth`: IndexedDB, с резервными вариантами хранения браузера. Приложение не переводит сессию в режим хранения только в памяти.
- Возврат на вкладку не отменяет незавершённую загрузку. Повторное подключение сохраняет текущую запись; смена аккаунта очищает только отображаемое состояние, не облачную историю.
- Экран старта появляется только после подтверждения пустой истории сервером. Отказ Firebase или отсутствие сети не считаются новым аккаунтом и не запускают новый марафон.
- При долгом подключении доступны повтор загрузки и выход. Коды ошибок Google и Firebase переводятся в конкретные сообщения, без вывода токенов и служебного ответа сервера.

Для GitHub Pages используется окно Google, а не автоматическое перенаправление через другой домен: [рекомендации Firebase по ограничениям стороннего хранилища](https://firebase.google.com/docs/auth/web/redirect-best-practices). Правила сохранения сессии: [Firebase Auth persistence](https://firebase.google.com/docs/auth/web/auth-state-persistence). Встроенный браузер мессенджера может ограничивать вход; в этом случае сайт нужно открыть в обычном браузере телефона.
